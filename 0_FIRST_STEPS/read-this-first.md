# 🟦 Read This First

This repository has a clear workflow and contribution process.  
Before opening issues or submitting pull requests, read this file carefully.

---

## 1. What This Repository Expects From You
- Follow the workflow and templates.
- Communicate clearly and professionally.
- Do not open blank issues.
- Do not use GitHub for questions or chat.
- Respect task assignments and boundaries.

---

## 2. Required Reading (Before Doing Anything)
You must read these four files from `0_READ_FIRST`:

1. `01_project_overview.md`
2. `04_git_workflow.md`
3. `02_coding_standards.md`
4. `03_coding_standards_checklist.md`

These give you the **minimum knowledge** needed to contribute.

---

## 3. How to Pick a Task
- Only pick tasks labeled **task**, **thinking**, or **good-first-issue**.
- Do not take tasks assigned to someone else.
- Thinking Tasks come **before** implementation tasks.
- Ask on WhatsApp if unsure — not GitHub.

See: `how-to-pick-a-task.md`

---

## 4. How to Open an Issue
Use the correct template:

- **Thinking Task** → analysis before coding  
- **Task** → implementation  
- **Bug Report** → reproducible bugs  
- **Feature Request** → new features  

Do not skip required fields.  
Do not open blank issues.

See: `how-to-write-a-good-issue.md`

---

## 5. How to Submit a Pull Request
Your PR must:

- Use the correct PR template  
- Be small and focused  
- Include screenshots for UI changes  
- Link the issue it solves  
- Contain no unrelated changes  
- Pass all checks  

See: `how-to-write-a-good-pr.md`

---

## 6. Communication Rules
- Use **WhatsApp** for questions.
- Use **Email** for sensitive matters.
- Use **GitHub** only for structured issues and PRs.
- Keep communication clear and concise.

---

## 7. Before You Start Working
Confirm the following:

- [ ] I read the required files in `0_READ_FIRST`
- [ ] I understand the task workflow
- [ ] I know which issue template to use
- [ ] I know how to write a proper PR
- [ ] I will ask questions on WhatsApp, not GitHub
