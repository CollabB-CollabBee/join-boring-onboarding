# **Project Overview**

This repository introduces the two core projects in our ecosystem: **SACS** and **Tabu**.  
Both projects share architectural principles, ethical foundations, and development standards — but they serve different functions and require different levels of contributor maturity.

This document explains:
- why onboarding exists  
- how contributors progress  
- where SACS and Tabu fit in the overall platform  
- why access to Tabu is by invitation only  

---

## **1. Why We Start With Onboarding**

Onboarding is not a formality — it is a **professional pipeline**.

Every contributor begins here because:
- we maintain strict coding, documentation, and collaboration standards  
- we work in grant‑aligned, audit‑ready environments  
- we protect the integrity of youth‑facing and community‑facing tools  
- we need to understand your coding habits before assigning real tasks  
- we want to support your early employability and professional growth  

Onboarding ensures:
- clean code  
- consistent Git discipline  
- accurate self‑presentation  
- traceable work  
- safe collaboration  

Only after completing onboarding can contributors move into project work.

---

## **2. SACS — Upskilling, Coaching & Social Care Tools**

**SACS (Social Architecture & Care System)** is the first project contributors join after onboarding.

SACS focuses on:
- upskilling contributors  
- building coaching and conflict‑mapping tools  
- developing small, modular features  
- experimenting safely without affecting youth‑facing systems  
- learning to work with our shared architecture  

SACS is intentionally designed as:
- a **training ground**  
- a **sandbox for learning clean code**  
- a **place to build confidence and competence**  

Contributors who demonstrate:
- reliability  
- clean code  
- good communication  
- respect for process  
- ability to follow documentation  

…can progress to more complex work.

---

## **3. Tabu — Youth‑Centred Communication & Conflict Mapping**

**Tabu** is our flagship project.  
It is youth‑centred, ethically sensitive, and built with strict quality and safety requirements.

Tabu involves:
- conflict‑mapping for classrooms and online communities  
- restorative communication tools  
- bias and heat detection  
- role and pattern analysis  
- culturally sensitive design  
- high‑integrity data handling  

Because of the ethical and technical complexity, **Tabu is invite‑only**.

Contributors are invited when they have:
- completed onboarding  
- demonstrated clean, maintainable code  
- shown strong Git discipline  
- contributed meaningfully to SACS  
- shown maturity in communication and collaboration  
- understood the mission and ethical boundaries  

Tabu is not a beginner project.  
It is a responsibility.

---

## **4. How the Progression Works**

```
Onboarding → SACS Upskilling → Tabu (Invite Only)
```

### **Onboarding**
Learn:
- clean code  
- Git discipline  
- professional presentation  
- documentation standards  
- audit‑ready workflows  

### **SACS**
Practice:
- real features  
- modular components  
- coaching tools  
- conflict‑mapping logic  
- safe experimentation  

### **Tabu**
Build:
- youth‑facing tools  
- sensitive communication systems  
- high‑integrity modules  
- grant‑aligned deliverables  

---

## **5. Why This Structure Exists**

This progression ensures:
- safety for youth and educators  
- quality for grant reviewers  
- traceability for audits  
- clarity for contributors  
- fairness in access  
- a structured learning path  

It also protects the mission:
**We build tools that support communities — not tools that cause harm through rushed or unskilled development.**

- understand the standards

- understand why we take onboarding seriously  

Your journey starts here — with clarity, structure, and professionalism.
